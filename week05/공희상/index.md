# 메인 메모리

프로세스는 실행 중인 프로그램이다. 실행하려면 프로그램의 명령어와 데이터가 메인 메모리에 있어야 한다. 메모리는 주소가 붙은 바이트의 배열이며, CPU는 프로그램 카운터가 가리키는 주소에서 명령어를 가져오고 load·store 명령으로 메모리에 접근한다.

## 메모리 보호

멀티프로그래밍 환경에서는 한 프로세스가 다른 프로세스나 운영체제의 메모리를 침범하면 안 된다. 연속 할당에서는 재배치 레지스터(base register)와 한계 레지스터(limit register)로 이를 검사한다.

- 허용되는 물리 주소 범위는 `base ≤ 물리 주소 < base + limit`이다.
- CPU가 만든 논리 주소가 `0 ≤ 논리 주소 < limit`일 때 물리 주소는 `base + 논리 주소`가 된다.
- 범위를 벗어나면 하드웨어가 트랩을 발생시킨다.

## 주소 바인딩

프로그램의 주소는 소스 코드에서는 변수 이름 같은 기호 주소이고, 컴파일·링크 과정에서는 재배치 가능한 주소가 된다. 실제 물리 메모리의 위치는 컴파일할 때, 프로그램을 적재할 때 또는 실행 중에 결정된다.

- 컴파일 시간 바인딩: 적재 위치를 미리 알 때 절대 주소를 만든다.
- 적재 시간 바인딩: 프로그램을 메모리에 올릴 때 재배치 가능한 주소를 실제 주소로 바꾼다.
- 실행 시간 바인딩: 실행 중 MMU가 논리 주소를 물리 주소로 변환한다.

## 논리 주소와 물리 주소, MMU

- 논리 주소(logical address): CPU가 생성하고 프로세스가 사용하는 주소
- 물리 주소(physical address): 실제 메모리 하드웨어의 주소

논리 주소 공간과 물리 주소 공간을 분리하면 프로그램은 실제 적재 위치를 몰라도 된다. 메모리 관리 장치(MMU)는 논리 주소를 물리 주소로 매핑하는 하드웨어이며, 재배치 레지스터는 이 매핑에서 base register 역할을 한다.

## 동적 로딩과 동적 링킹

동적 로딩(dynamic loading)은 프로그램 전체를 한꺼번에 적재하지 않고, 루틴이 호출될 때 메모리에 올리는 방식이다. 메모리 사용량을 줄일 수 있고, 필요하면 재배치 가능한 링킹 로더가 주소 테이블을 갱신한다.

정적 링킹(static linking)은 라이브러리 코드를 실행 파일에 함께 넣는다. 동적 링킹(dynamic linking)은 실행 시간에 라이브러리와 연결한다. DLL 같은 공유 라이브러리는 여러 프로세스가 같은 라이브러리 코드를 공유할 수 있다.

## 연속 메모리 할당

연속 메모리 할당(contiguous memory allocation)은 프로세스 전체를 하나의 연속된 메모리 구역에 넣는 방식이다. 프로세스의 할당과 해제를 반복하면 빈 구역인 hole이 생기며, 요청 크기 `n`을 어느 hole에 넣을지 정해야 한다.

- 최초 적합(first-fit): 처음 발견한 충분히 큰 hole에 할당한다.
- 최적 적합(best-fit): 들어갈 수 있는 hole 중 가장 작은 곳에 할당한다.
- 최악 적합(worst-fit): 들어갈 수 있는 hole 중 가장 큰 곳에 할당한다.

200MB 요청이 들어오면 205MB hole에 최초 적합 또는 최적 적합으로 할당하여 5MB hole이 남을 수 있다. 최악 적합이 300MB hole을 고르면 100MB hole이 남는다.

외부 단편화(external fragmentation)는 충분한 총 여유 공간이 있어도 작은 hole로 흩어져 연속된 요청을 받을 수 없는 문제다. 내부 단편화(internal fragmentation)는 할당한 블록 안에서 남은 공간을 다른 요청에 쓰지 못하는 문제다. 연속 할당은 외부 단편화가 문제이고, 고정 크기 블록을 쓰는 페이징은 마지막 페이지 등에서 내부 단편화가 생길 수 있다.

## 페이징

페이징(paging)은 프로세스의 논리 주소 공간을 같은 크기의 페이지(page)로, 물리 메모리를 같은 크기의 프레임(frame)으로 나누어 페이지를 임의의 빈 프레임에 배치하는 방식이다. 프로세스의 물리 메모리 배치가 불연속적이어도 되므로 외부 단편화가 없고 압축도 필요하지 않다.

논리 주소는 페이지 번호 `p`와 페이지 내부 오프셋 `d`로 나뉜다. 페이지 테이블은 `p`를 프레임 번호 `f`로 바꾸며, 물리 주소는 `f`와 `d`로 구성한다. 논리 주소 공간이 `2^m`, 페이지 크기가 `2^n`이면 페이지 번호는 `m-n`비트, 오프셋은 `n`비트, 페이지 개수는 `2^(m-n)`개다. 페이지 크기는 보통 4KB부터 1GB 사이의 2의 거듭제곱으로 정한다.

빈 프레임은 연결 리스트 등으로 관리할 수 있다. 예를 들어 빈 프레임 목록이 `14 → 13 → 18 → 20`이면 새 프로세스의 페이지를 이 순서로 배치할 수 있다.

### 페이지 테이블과 TLB

페이지 테이블은 보통 메인 메모리에 있고, PTBR(page-table base register)이 시작 주소를 가리킨다. TLB(translation look-aside buffer)는 최근 페이지 테이블 항목을 보관하는 고속 캐시다.

- TLB hit: 페이지 번호가 TLB에 있어 바로 프레임 번호를 찾는다.
- TLB miss: TLB에 없어 메인 메모리의 페이지 테이블을 읽은 뒤 프레임 번호를 찾는다.

TLB 접근 시간을 무시하고 메모리 접근 시간이 10ns, hit ratio가 80%라고 하면 다음과 같다.

```text
EAT = 0.80 × 10 + 0.20 × 20 = 12ns
```

miss에서는 페이지 테이블과 실제 데이터에 각각 접근하므로 20ns가 든다.

### 보호와 공유

페이지 테이블 항목의 protection bit는 읽기·쓰기·실행 권한을 제한한다. valid-invalid bit는 해당 페이지가 프로세스의 논리 주소 공간에 있는지 표시한다. 예를 들어 0~5번 페이지가 valid이고 6~7번 페이지가 invalid라면, 6~7번 접근은 불법이므로 트랩이 발생한다.

공유 페이지(shared page)는 `libc` 같은 재진입 가능(reentrant) 라이브러리 코드를 여러 프로세스가 하나의 물리 프레임으로 공유하게 한다. 재진입 가능한 코드는 실행 중 자신을 수정하지 않는다. 프로세스마다 페이지 테이블은 별도로 가지되, 공유 코드에 해당하는 각 페이지 테이블 항목이 같은 프레임을 가리킨다.

## 페이지 테이블 구조

논리 주소 공간이 커지면 페이지 테이블도 커지므로 구조화가 필요하다.

- 계층적 페이징(hierarchical paging): 페이지 테이블을 여러 단계로 나눈다.
- 해시 페이지 테이블(hashed page table): 가상(논리) 페이지 번호를 해시해 버킷을 찾고, 연결된 항목의 가상 페이지 번호와 필요하면 PID를 비교한 뒤 프레임 번호를 찾는다. 큰 주소 공간에서 사용한다.
- 역 페이지 테이블(inverted page table): 프레임마다 하나의 항목을 두고, 그 프레임을 사용하는 PID와 논리 페이지 번호를 저장한다.

## 스와핑

표준 스와핑(standard swapping)은 프로세스 전체를 메인 메모리와 보조 기억장치(backing store) 사이에서 옮기는 방식이다. 메모리에서 보조 기억장치로 내보내는 것을 swap out, 다시 올리는 것을 swap in이라고 한다. 프로세스 전체 이동은 비용이 크다.

가상 메모리에서는 필요한 페이지만 보조 기억장치와 교환하는 페이지 단위 스와핑을 사용한다. 이때는 page out, page in이라고 부르며, 일부 페이지만 메모리에 올려 더 많은 프로세스를 동시에 유지할 수 있다. 이 방식은 다음 장의 가상 메모리와 연결된다.
