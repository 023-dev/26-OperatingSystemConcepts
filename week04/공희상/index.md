# CPU 스케줄링

CPU 코어가 하나라면 한 번에 하나의 프로세스만 실행할 수 있다.
그런데 실행 중인 프로세스가 I/O를 기다리는 동안에도 CPU가 그대로 멈춰 있다면 자원이 낭비된다.

운영체제는 CPU가 쉬지 않도록 준비 큐(Ready Queue)에 있는 다른 프로세스에 CPU를 넘겨준다.
이처럼 여러 프로세스 중 다음에 실행할 프로세스를 선택하는 일을 **CPU 스케줄링**이라고 한다.

---

## CPU-I/O 버스트 사이클

프로세스의 실행은 다음 두 구간을 반복한다.

- CPU 버스트(CPU Burst): CPU에서 명령어를 실행하는 구간
- I/O 버스트(I/O Burst): 입출력 완료를 기다리는 구간

프로세스는 CPU 버스트로 시작해 CPU 버스트와 I/O 버스트를 번갈아 수행하고,
마지막 CPU 버스트가 끝나면 종료 시스템 콜을 호출한다.

프로세스의 성격에 따라 버스트의 분포도 달라진다.

- CPU-bound 프로세스: 긴 CPU 버스트가 적게 나타난다.
- I/O-bound 프로세스: 짧은 CPU 버스트가 자주 나타난다.

스케줄링 알고리즘은 이러한 차이를 고려해야 한다.

---

## CPU 스케줄러

CPU가 유휴 상태가 되면 단기 스케줄러(Short-term Scheduler)가
준비 큐에 있는 프로세스 중 하나를 선택해 CPU를 할당한다.

준비 큐는 반드시 FIFO일 필요가 없다.
스케줄링 알고리즘에 따라 큐의 정렬 기준이나 자료구조가 달라질 수 있으며,
큐에는 프로세스 자체가 아니라 PCB 형태의 레코드가 저장된다.

### 스케줄링이 필요한 시점

CPU 스케줄링 결정은 다음과 같은 상태 변화에서 발생한다.

1. 실행(Running) → 대기(Waiting)
2. 실행(Running) → 준비(Ready)
3. 대기(Waiting) → 준비(Ready)
4. 프로세스 종료

1번과 4번은 현재 프로세스가 더 이상 CPU를 사용할 수 없으므로 반드시 다른 프로세스를 선택해야 한다.
2번과 3번은 현재 프로세스를 계속 실행할 수도 있고 다른 프로세스에 CPU를 넘길 수도 있다.

### 선점과 비선점

**비선점 스케줄링(Non-preemptive Scheduling)**은 프로세스가 CPU를 할당받으면
종료되거나 대기 상태로 전환될 때까지 CPU를 사용한다.

**선점 스케줄링(Preemptive Scheduling)**은 실행 중인 프로세스에서 CPU를 빼앗아
다른 프로세스에 할당할 수 있다.

선점형은 응답성을 높일 수 있지만 공유 데이터에 동시에 접근하면서 경쟁 조건이 발생할 수 있다.
또한 커널이 시스템 콜을 처리하는 도중 선점된다면 커널 자료구조의 일관성도 고려해야 한다.

---

## 디스패처

디스패처(Dispatcher)는 CPU의 제어권을 스케줄러가 선택한 프로세스에 넘기는 모듈이다.

디스패처는 다음 작업을 수행한다.

- 문맥 교환(Context Switch)
- 커널 모드에서 사용자 모드로 전환
- 사용자 프로그램의 실행 위치로 이동

한 프로세스를 멈추고 다른 프로세스의 실행을 시작하기까지 걸리는 시간을
**디스패치 지연(Dispatch Latency)**이라고 한다.

디스패처는 문맥 교환이 발생할 때마다 실행되므로 가능한 빨라야 한다.

---

## 스케줄링 평가 기준

스케줄링 알고리즘은 시스템의 목적에 맞는 기준으로 평가해야 한다.

- CPU 이용률(CPU Utilization): CPU가 작업을 처리한 시간의 비율
- 처리량(Throughput): 단위 시간 동안 완료한 프로세스 수
- 반환 시간(Turnaround Time): 프로세스 제출부터 완료까지 걸린 전체 시간
- 대기 시간(Waiting Time): 준비 큐에서 기다린 시간의 합
- 응답 시간(Response Time): 요청을 제출한 뒤 첫 응답이 나오기까지 걸린 시간

일반적으로 CPU 이용률과 처리량은 높이고,
반환 시간·대기 시간·응답 시간은 줄이는 것이 목표다.

## 스케줄링 알고리즘

### 선입 선처리(FCFS)

FCFS(First-Come, First-Served)는 CPU를 먼저 요청한 프로세스에 먼저 CPU를 할당한다.
FIFO 큐로 간단하게 구현할 수 있는 비선점 알고리즘이다.

| 프로세스 | CPU 버스트 |
| --- | ---: |
| P1 | 24ms |
| P2 | 3ms |
| P3 | 3ms |

P1 → P2 → P3 순서라면 대기 시간은 각각 0ms, 24ms, 27ms이고 평균은 17ms다.
P2 → P3 → P1 순서라면 대기 시간은 각각 0ms, 3ms, 6ms이고 평균은 3ms다.

FCFS는 실행 순서에 따라 평균 대기 시간이 크게 달라진다.
특히 실행 시간이 긴 프로세스 하나 때문에 짧은 프로세스들이 오래 기다리는 현상을
**호위 효과(Convoy Effect)**라고 한다.

### 최단 작업 우선(SJF)

SJF(Shortest-Job-First)는 다음 CPU 버스트가 가장 짧은 프로세스에 CPU를 할당한다.
평균 대기 시간을 최소화한다는 장점이 있다.

하지만 다음 CPU 버스트의 길이를 미리 정확히 알 수 없으므로,
이전 CPU 버스트를 이용해 다음 값을 예측한다.

```text
τ(n+1) = α × t(n) + (1 - α) × τ(n)
```

- `t(n)`: 가장 최근 CPU 버스트의 실제 길이
- `τ(n)`: 이전에 예측한 CPU 버스트 길이
- `α`: 최근 값과 과거 값의 반영 비율 (`0 ≤ α ≤ 1`)

SJF는 선점형과 비선점형으로 나뉜다.
선점형 SJF는 새로 도착한 프로세스의 남은 실행 시간이 현재 프로세스보다 짧으면 CPU를 빼앗는다.
이를 **최단 잔여 시간 우선(SRTF, Shortest-Remaining-Time-First)**이라고 한다.

### 우선순위 스케줄링

우선순위 스케줄링(Priority Scheduling)은 우선순위가 가장 높은 프로세스에 CPU를 할당한다.
SJF도 다음 CPU 버스트가 짧을수록 높은 우선순위를 주는 우선순위 스케줄링으로 볼 수 있다.

낮은 우선순위의 프로세스가 계속 선택되지 못하는 현상을
**기아(Starvation)** 또는 **무한 봉쇄(Indefinite Blocking)**라고 한다.

이를 완화하기 위해 오래 기다린 프로세스의 우선순위를 점진적으로 높이는
**노화(Aging)** 기법을 사용한다.

### 라운드 로빈(RR)

라운드 로빈(Round Robin)은 시분할 시스템을 위해 설계된 선점형 알고리즘이다.
준비 큐를 순환 큐로 사용하고 각 프로세스에 일정한 시간 할당량을 부여한다.

1. 준비 큐의 첫 프로세스에 CPU를 할당한다.
2. 시간 할당량이 지나면 타이머 인터럽트가 발생한다.
3. 끝나지 않은 프로세스를 준비 큐의 뒤로 보낸다.
4. 다음 프로세스가 CPU를 사용한다.

시간 할당량(Time Quantum)의 크기가 성능을 좌우한다.

- 너무 크면 FCFS와 비슷해진다.
- 너무 작으면 문맥 교환이 자주 발생해 오버헤드가 커진다.

따라서 시간 할당량은 문맥 교환 시간보다 충분히 길어야 한다.

### 다단계 큐

다단계 큐(Multilevel Queue)는 프로세스를 성격에 따라 여러 준비 큐로 나눈다.

예를 들어 포그라운드 프로세스에는 라운드 로빈을,
백그라운드 프로세스에는 FCFS를 적용할 수 있다.
큐 사이에도 고정 우선순위나 일정한 CPU 시간 비율과 같은 별도의 스케줄링이 필요하다.

프로세스는 처음 배정된 큐에서 다른 큐로 이동하지 않는다.
구조는 단순하지만 낮은 우선순위 큐에서 기아가 발생할 수 있다.

### 다단계 피드백 큐

다단계 피드백 큐(Multilevel Feedback Queue)는 프로세스가 큐 사이를 이동할 수 있다.

- CPU를 오래 사용하는 프로세스는 낮은 우선순위 큐로 이동한다.
- 오래 기다린 프로세스는 높은 우선순위 큐로 이동할 수 있다.

프로세스의 실행 특성에 맞춰 우선순위를 조정할 수 있어 유연하지만,
다음 조건을 모두 정해야 하므로 설계가 복잡하다.

- 큐의 개수
- 각 큐의 스케줄링 알고리즘
- 프로세스를 상위 또는 하위 큐로 이동시키는 조건
- 처음 들어갈 큐를 정하는 조건

## 스레드 스케줄링

사용자 수준 스레드와 커널 수준 스레드는 서로 경쟁하는 범위가 다르다.

### 프로세스 경쟁 범위(PCS)

PCS(Process-Contention Scope)는 같은 프로세스에 속한 사용자 스레드끼리
사용 가능한 LWP 또는 커널 스레드를 얻기 위해 경쟁하는 방식이다.
스레드 라이브러리가 스케줄링을 담당한다.

### 시스템 경쟁 범위(SCS)

SCS(System-Contention Scope)는 커널 스레드들이 시스템 전체에서
물리 CPU를 얻기 위해 경쟁하는 방식이다.
커널이 스케줄링을 담당한다.

일대일 스레딩 모델을 사용하는 일반적인 운영체제에서는 커널 스레드가 직접 CPU를 경쟁하므로 SCS가 사용된다.

## 다중 처리기 스케줄링

CPU가 여러 개라면 여러 프로세스를 실제로 병렬 실행할 수 있지만,
CPU 사이의 부하 분배와 캐시 효율까지 고려해야 한다.

### 비대칭 다중 처리와 대칭 다중 처리

**비대칭 다중 처리(AMP)**는 하나의 주 프로세서가 스케줄링과 I/O 등 시스템 활동을 담당한다.
구현은 단순하지만 주 프로세서가 병목이나 단일 장애점이 될 수 있다.

**대칭 다중 처리(SMP)**는 각 프로세서가 스스로 스케줄링한다.
공통 준비 큐를 사용하거나 프로세서마다 별도의 준비 큐를 둘 수 있다.
공통 큐를 사용한다면 여러 프로세서의 동시 접근을 동기화해야 한다.

현대 운영체제는 일반적으로 SMP를 지원한다.

### 프로세서 친화성

프로세스가 특정 프로세서에서 실행되면 사용한 데이터가 해당 프로세서의 캐시에 남는다.
프로세스를 다른 프로세서로 옮기면 기존 캐시의 이점을 잃고 새 캐시를 채워야 한다.

이 비용을 줄이기 위해 가능한 한 같은 프로세서에서 계속 실행하려는 성질을
**프로세서 친화성(Processor Affinity)**이라고 한다.

- 연성 친화성(Soft Affinity): 같은 프로세서에서 실행하려고 노력하지만 보장하지 않는다.
- 강성 친화성(Hard Affinity): 프로세스가 실행될 프로세서 집합을 명시한다.

### 부하 균등화

SMP에서는 모든 프로세서가 비슷한 양의 작업을 맡도록 부하를 분산해야 한다.

- Push Migration: 별도의 작업이 부하를 감시하다가 바쁜 프로세서의 작업을 다른 곳으로 보낸다.
- Pull Migration: 쉬고 있는 프로세서가 바쁜 프로세서의 작업을 가져온다.

작업을 옮기면 부하는 고르게 분산되지만 프로세서 친화성이 깨질 수 있으므로 두 목표 사이의 균형이 필요하다.

### 멀티코어와 하드웨어 스레드

프로세서는 캐시 미스 등으로 메모리의 데이터를 기다리는 동안 실행을 멈출 수 있다.
이를 **메모리 정지(Memory Stall)**라고 한다.

하나의 코어에 여러 하드웨어 스레드를 두면 한 스레드가 멈춘 동안 다른 스레드가 실행되어
코어의 활용도를 높일 수 있다.

- 거친 다중 스레딩: 긴 지연이 발생할 때 다른 스레드로 전환한다.
- 세밀한 다중 스레딩: 명령어 주기처럼 짧은 간격마다 스레드를 전환한다.

## 실시간 CPU 스케줄링

실시간 시스템은 단순히 평균 성능을 높이는 것보다 정해진 시간 안에 응답하는 것이 중요하다.

사건이 발생한 시점부터 해당 서비스가 시작될 때까지의 시간을 **레이턴시(Latency)**라고 한다.

- 인터럽트 레이턴시: 인터럽트 발생부터 인터럽트 서비스 루틴이 시작되기까지 걸리는 시간
- 디스패치 레이턴시: 실행 중인 프로세스를 멈추고 다른 프로세스를 시작하기까지 걸리는 시간

실시간 스케줄링은 두 레이턴시를 예측 가능하고 짧게 유지해야 한다.

## Linux CFS

Linux의 CFS(Completely Fair Scheduler)는 각 태스크에 고정된 시간 할당량을 나누는 대신,
모든 실행 가능한 태스크가 적어도 한 번씩 실행될 목표 지연 시간(Targeted Latency)을 기준으로
CPU 시간을 배분한다.

CFS는 각 태스크가 사용한 CPU 시간을 `vruntime`이라는 가상 실행 시간으로 관리한다.
낮은 우선순위의 태스크는 실제 실행 시간보다 `vruntime`이 더 빠르게 증가하므로
다음 CPU를 할당받기까지 더 오래 기다린다.

실행 가능한 태스크는 `vruntime`을 기준으로 정렬되며,
가장 작은 `vruntime`을 가진 태스크가 다음 실행 대상으로 선택된다.
따라서 CPU를 적게 사용한 태스크가 실행 기회를 먼저 얻어 공정성을 유지한다.

## 스케줄링 알고리즘 평가

좋은 스케줄링 알고리즘은 시스템의 목적과 작업 부하에 따라 달라진다.
먼저 CPU 이용률, 응답 시간, 처리량과 같은 평가 기준을 정한 뒤 알고리즘을 비교해야 한다.

### 결정론적 모델링

결정론적 모델링(Deterministic Modeling)은 미리 정한 작업 부하를 각 알고리즘에 적용해
평균 대기 시간과 같은 성능을 계산한다.

간단하고 빠르지만 계산 결과가 주어진 입력에만 적용된다는 한계가 있다.

### 큐잉 모델

큐잉 모델(Queuing Model)은 CPU와 I/O 버스트의 분포,
프로세스 도착률과 서비스율을 이용해 성능을 계산한다.

평균 큐 길이를 `n`, 평균 대기 시간을 `W`, 평균 도착률을 `λ`라고 하면
리틀의 법칙(Little's Law)은 다음과 같다.

```text
n = λ × W
```

실제 시스템을 근사할 수 있지만 독립성 등 여러 가정이 필요하고,
분석 가능한 알고리즘과 분포가 제한적이다.

### 시뮬레이션

시뮬레이션은 프로세스와 스케줄러의 동작을 프로그램으로 모델링해 알고리즘의 성능을 측정한다.
실제 시스템의 작업 기록을 입력으로 사용하면 더 현실적인 결과를 얻을 수 있다.

결정론적 모델이나 큐잉 모델보다 구체적으로 평가할 수 있지만,
시뮬레이터를 만들고 실행하는 데 많은 시간과 비용이 든다.
